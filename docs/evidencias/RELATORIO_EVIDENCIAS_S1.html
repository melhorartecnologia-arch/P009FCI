2 · Como o usuário verifica (roteiro de acesso)

Ambiente: aplicação Node.js servida em http://<servidor>:3000 com PostgreSQL local na mesma instância (VPS AWS Ubuntu — instalação por scripts/install-vps.sh). Em desenvolvimento: npm run setup && npm start.

Usuários de verificação (senha inicial cci@2026, definida em SEED_SENHA; trocar no 1º acesso):

E-mailÁreaPerfil / uso na verificação
ti@cci.localTIAdministrador — edita integrações, parâmetros, usuários
custos@cci.localCustosSimulador — cria cenários; comprova o modo consulta (RF-100)
controladoria@cci.localControladoriaValidador — congela cenário (RN-10)
fiscal@cci.local · pricing@cci.local · compras@cci.local—Perfis de consulta/simulação por área

Roteiro mínimo de verificação (10 min):

  1. Entrar como ti@cci.local → menu Integrações: conferir 5 fontes, testar conexão, sincronizar, abrir Mapeamento e Execuções (RF-090…095).
  2. Menu Parâmetros: editar gatilho (5 → 7 p.p.), salvar; incluir/excluir alíquota; alterar um MV_FCI (RF-096…099).
  3. Sair e entrar como custos@cci.local → ＋ Novo cenário: cenário nasce v1/Rascunho com estrutura carregada (RF-001/RF-002); abrir a simulação e a aba Estrutura.
  4. Voltar a Integrações ainda como Custos: tela em modo consulta com aviso de restrição (RF-100).
  5. Menu Alertas: quantidade reflete o gatilho ajustado no passo 2 (RF-099).

Reprodução técnica: npm test executa os 11 testes de aceite da seção 5 contra o banco configurado no .env.
